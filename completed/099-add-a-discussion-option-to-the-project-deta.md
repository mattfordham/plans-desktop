# Add A Discussion Option To The Project Detail Panel

**ID:** 099

## What
Add a discussion option to the project detail panel. This would be a fixed footer on the bottom right that spans full width and would allow for conversation with the agent about the plan.

## Why
Adds value by letting the user ask the agent a free-text question about the plan they are looking at — "why this approach?", "what does step 3 mean?", "is there a simpler way?" — without leaving the detail pane or opening one of the action sheets. It turns the plan-detail column from a one-way document into a place to interrogate the plan, reusing the same Agent-SDK hand-off that already powers Elaborate/Execute/Refine.

## How Summary
A persistent full-width composer pinned to the bottom of `PlanDetailView` (via `.safeAreaInset(edge: .bottom)`, #096-safe) lets the user hold a **multi-turn, read-only conversation** with the agent about the plan, rendered **inline in the detail column** beneath the plan. Each turn is one `run-task.js --mode discuss` spawn; continuity comes from the Agent SDK's session resume — the runner emits the `session_id` (from `system/init`) and a clean `reply` (from `result.result`), and follow-ups pass `--resume <id>`. Conversation state lives in a `DiscussionThread` owned by `TaskRunner` (keyed per project+task, separate from `runs`) so it survives plan switches and never collides with execute/elaborate runs, spinners, or failure badges. Read-only is enforced by tool restrictions (no Write/Edit/Bash), not just prompt wording.

## Issues
- [x] Discussion reply never appears: the turn shows "thinking" then stops with no reply or error. Cause: `TaskRun.handleTermination` finishes the run as soon as the process exits, but the last stdout chunk (the large `reply` + `done` lines) can arrive after that. The thread has already cleared `activeRun`, so it drops them, and the partial reply line buffered at exit is garbled by the forced trailing newline. Log: `process terminated: task=049 status=0 lines=13 hasSummary=false`; running the same command directly emits `reply` + `done` correctly.
- [x] Layout: the conversation should live in the same panel as the composer — a scrolling conversation panel taking the bottom half of the detail view (plan above, conversation transcript + composer below), not a "Discussion" section appended to the end of the plan.
- [x] Question bubbles are low contrast (dark accent tint on the dark panel) — make the user's message clearly legible/distinct.
- [x] No way to close or cancel the current conversation — add a close control that ends it (stopping any in-flight turn) and collapses the panel, plus a way to cancel a pending turn.
- [x] Agent replies render too large/prominent with colored headings — use a smaller, compact text style for replies and plain (non-colored) headings.
